# Keepers: testing

Expected results come from a reference or from how a fixture was built, never from running the code.
Golden files are the specification, not a cache.

## 1. Layers and where they live

| Layer | Location | Runner |
|---|---|---|
| Unit tests | beside the code, `#[cfg(test)]` | `cargo test` |
| Module tests | `crates/keepers-core/tests/NN_slug.rs` (for example `01_ingest_and_previews.rs`); module 09 in `crates/keepers-publik/tests/09_publik_second_opinion.rs` and, for the self-test, `app/src-tauri/tests/09_publik_self_test.rs` | `cargo test` |
| Golden CLI cases | `tests/cases/NN-slug/<case>/`, driven by `crates/keepers-cli/tests/golden.rs` | `cargo test -p keepers-cli --test golden` |
| Property tests | inside the module test files, `proptest` with a fixed seed per case | `cargo test` |
| Always-on invariants | `crates/keepers-core/tests/{hygiene,originals_untouched,source_rules}.rs` | `cargo test` |
| UI logic | `app/src/**/<name>.test.ts` (Vitest) | `npm --prefix app test` |
| Launch smoke | `app/e2e/smoke.test.mjs` (tauri-driver + WebdriverIO), Ubuntu only | CI job `e2e-smoke` |
| Quality gates | `keepers gates`, `scripts/gates.sh` | before a release; when touching scoring, faces, grouping or ranking |

A module's tests are `tests/cases/NN-slug/`, the code test files its spec names, and fixture
generator additions (`crates/keepers-fixtures/`), and nothing else.

## 2. Commands

- Everything CI runs except the smoke: `sh scripts/verify.sh` (PowerShell: `scripts\verify.ps1`). In
  order, stopping at the first failure: `npm --prefix app run build`, `typecheck`, `lint`,
  `format:check`, `test`; `cargo fmt --all --check`; `cargo clippy --workspace --all-targets -- -D warnings`;
  `cargo deny check licenses`; the npm licence check; the fixture generator with `--check`;
  `cargo test --workspace`.
- One module: `cargo test -p keepers-core --test 02_technical_scores`.
- One module's goldens: `GOLDEN_FILTER=02-technical-scores cargo test -p keepers-cli --test golden`.
- Regenerate goldens for a new case: `UPDATE_GOLDEN=1 GOLDEN_FILTER=<module> cargo test -p keepers-cli --test golden`,
  then read the diff line by line. Refused without `GOLDEN_FILTER`.
- Fixtures: `cargo run -p keepers-fixtures -- --out tests/fixtures/gen --seed 1`;
  check: `… --check tests/fixtures/gen.sha256`; after an intended change: `… --write-manifest tests/fixtures/gen.sha256`.
- Gates: `sh scripts/gates.sh` (generated set always; real RAW and evaluation sets when present).

## 3. The golden harness

Each case is a directory with `case.toml`, `expected.json` and optionally `expected/` files.

```toml
description = "scan reads EXIF from the generated exif set"
fixture = "gen/exif"                      # under tests/fixtures/
copy_fixture = false                      # true: copy into a temp dir first (export cases)
args = ["scan", "{fixture}", "--json", "--data-dir", "{tmp}"]
exit_code = 0
stdout = "expected.json"                  # compared as JSON
requires_models = []                      # e.g. ["yunet-2026may"]; the case skips with a message if absent
requires = []                             # e.g. ["raw-samples"]
env = { KEEPERS_FIXED_CLOCK = "2026-01-01T00:00:00.000Z" }

[tolerance]                               # JSON Pointer; `*` matches any array index
"/frames/*/sharpness/lap_var" = { rel = 1e-4 }
"/frames/*/exposure/clip_high_pct" = { abs = 1.5 }

[match]                                   # regular expressions for values that legitimately vary
"/version" = '^\d+\.\d+\.\d+(-[0-9A-Za-z.]+)?$'

[ignore]
paths = ["/summary/elapsed_ms"]

[files]                                   # files the command must write, compared byte for byte
"{fixture}/IMG_0001.xmp" = "expected/IMG_0001.xmp"
```

Rules: keys missing from either side fail (no silent extra fields); numbers without a tolerance
compare exactly; `{tmp}` is a fresh data directory per case; `{fixture}` is the fixture path (or its
copy). The harness sets `KEEPERS_FIXED_CLOCK` for every case and runs the `keepers` binary built by
Cargo. Its comparison logic has its own unit tests (`crates/keepers-cli/tests/support/compare.rs`).

## 4. Fixtures and what each proves by construction

Generated by `crates/keepers-fixtures` (seed 1; integer maths and `libm` only; JPEGs from the `image`
encoder; EXIF by a minimal in-house writer) into `tests/fixtures/gen/` (ignored). The committed
`tests/fixtures/gen.sha256` proves the output is bit-identical on Windows and Linux. Each set writes a
`truth.toml` with the facts it was built from.

| Set | Module | Contents | Proves |
|---|---|---|---|
| `basic/` | 00 | 3 JPEGs: base scene, σ 2 blur, +1 EV | the generator and harness work |
| `exif/` | 01 | 8 JPEGs with known Make, Model, LensModel, times, sub-seconds, offsets, orientation 1/3/6/8, one with GPS and serial tags, one with no date | EXIF values; GPS and serial never output; ordering |
| `containers/` | 01 | one synthetic file per family (`.cr2 .nef .arw .orf .rw2 .dng` TIFF-structured, `.cr3` ISO-BMFF, `.raf`), each with a 160 × 120 and a 1536 × 1024 JPEG preview; `broken/` truncated and mislabelled copies | every preview path; the largest is chosen; per-file errors |
| `pairs/` | 01 | `IMG_0001.dng` + `IMG_0001.jpg`, a lone JPEG, a byte-identical copy | pairing; duplicate handling |
| `blur-ladder/` | 02 | base scene 1536 × 1024 at Gaussian σ 0, 0.5, 1, 2, 4, 8 | sharpness ordering |
| `exposure/` | 02 | grey ramp (column value `floor(255x/(W−1))`) shifted −2 to +2 EV in linear light; flat patches of known area at 255 and 0 | clip and crush percentages from the sRGB formula |
| `motion/`, `dof/` | 02 | linear motion blur of length 15 at 0°, 90°, 45°; sharp centre with a σ 4 surround | motion angle; tile maximum versus global |
| `bursts/` | 04 | bursts of 5, 3 and 4 frames 0.2 s apart (shifts of 0 to 4 px, seeded noise); a near-duplicate pair 200 s apart; 4 distinct singletons 30 s apart | exact groups |
| `long-burst/` | 04 | 50 frames 0.1 s apart except one 0.5 s gap between index 24 and 25 | the 40-frame split rule |
| `wedding-mini/` | 05 | 40 frames in 3 scenes with planted blur, exposure faults and bursts, with the expected flags and reason codes in `truth.toml` | the automatic cull and its reasons |
| `export/` | 07 | synthetic `.cr3`, `.dng`, `.jpg` and a pair, plus existing sidecars with foreign namespaces | sidecar bytes and merges |
| `second-opinion/` | 09 | a 6000 × 4000 preview carrying EXIF, XMP, ICC and IPTC segments; six seeded-noise frames | stripping and the size budget |

Other fixtures:

- `tests/fixtures/cc0/`: 8 to 12 CC0 or public-domain photos of people (never anyone known to a
  contributor), each with its source URL and licence in `THIRD_PARTY.md`, and `labels.toml` written by
  a person looking at each image before any code runs: face count, and per clearly visible face the eye
  state. Module 03.
- `tests/fixtures/raw-samples.toml`: URL, SHA-256 and licence of each real RAW sample from
  raw.pixls.us (only files whose listed licence is CC0; verify at 01), with expected make, model and
  preview size recorded once from ExifTool output (its version recorded). Downloaded to
  `tests/fixtures/raw/` (ignored) by `scripts/fetch-raw-samples.sh` in the CI job; tests skip with
  "skipped: raw samples not downloaded (scripts/fetch-raw-samples.sh)".
- Models: never committed. `scripts/fetch-models.sh` downloads the registry's files into
  `KEEPERS_MODELS_DIR`; tests that need one skip with "skipped: model <id> not installed
  (scripts/fetch-models.sh)".
- `eval-data/` (ignored): the maintainer's private shoots for the agreement gate (module 08). Only
  aggregate numbers ever leave it.

## 5. References

Standards: TIFF 6.0; EXIF 2.32 (CIPA DC-008); DNG 1.7; ISO/IEC 14496-12; JPEG T.81 and JFIF 1.02;
IEC 61966-2-1 (sRGB); ISO 16684-1 and XMP Part 3; RFC 8259 (JSON). Papers: Pech-Pacheco et al. 2000;
Krotkov 1987; Immerkær 1996; Bigün and Granlund 1987; Soukupová and Čech 2016; Wu et al. 2023 (YuNet);
Radford et al. 2021 (CLIP). Format write-ups (documentation only, never source): public descriptions
of CR3, RAF and ORF structures and ExifTool's tag name tables. Editors' own documentation for XMP
behaviour (module 07). Clean-room: never open the source of exiv2, ExifTool, LibRaw, rawloader,
darktable or any GPL, AGPL or source-available project while writing a module.

## 6. Quality gates

`keepers gates --set generated|raw|eval:<name> --json` (module 08) reports:

| Metric | Set | Threshold |
|---|---|---|
| frames per minute, whole pipeline, CPU | raw, eval | set at 08 when first measured (target ≥ 300 for 24 MP) |
| time to the first 100 thumbnails | raw | set at 08 (target ≤ 3 s) |
| peak memory | raw, eval | set at 08 (target ≤ 2 GB for 6,000 frames) |
| reject precision and recall | eval | set at 08 (target ≥ 0.80) |
| best-frame agreement per group | eval | set at 08 (target ≥ 0.60) |
| eye-state accuracy | cc0 | ≥ 0.90 (module 03) |

Thresholds, once measured, are written into `CONTRIBUTING.md` under "Quality gates" with the date and the
machine class (never a hostname). A scaled-down gate runs in the normal suite: the `wedding-mini` set
analyses at ≥ 1 frame a second in a debug build with peak memory under 1 GB.

## 7. Always-on invariant tests

- `originals_untouched.rs` (from 01): hashes and mtimes of every fixture original before and after
  scan, score, faces, group, cull, export (all targets, copy and move to another folder) and
  second-opinion dry runs; all equal (moved files are checked at their destination).
- `source_rules.rs` (from 01): write-capable file APIs only in the allowed modules
  (`docs/ARCHITECTURE.md` §7); no `std::time::SystemTime::now` or `rand` outside `env.rs`.
- Determinism (from 02): two runs byte-identical; enumeration order shuffled through the injected
  directory lister gives identical documents; 1 and 8 threads give identical documents.
- Logs (from 01): a run on a copy of a fixture renamed to `zz-private-folder-name` with files named
  `zz-private-file-*` leaves `logs/keepers.log` containing neither string nor any EXIF value.

## 8. Source-hygiene test

A test that fails the build when a file about to be published contains something that would identify
a person or a machine, or something shaped like a secret. It runs in the normal suite, so in `verify`
and CI, and names no person and no address.

**Where it lives**: `crates/keepers-core/tests/hygiene.rs`, walking up from `CARGO_MANIFEST_DIR` to the
repository root (a root `tests/` folder is never compiled in a virtual workspace).

**Which files**: the output of `git ls-files -z --cached --others --exclude-standard`, skipping paths
that no longer exist, so ignored files are never scanned. Without git, walk the tree skipping every path `.gitignore` ignores, plus `.git`,
`node_modules`, `target`, `dist`, `build`, `out`, `coverage`, `release`, `.venv`, `__pycache__`, and
the root `models/` and `eval-data/` folders. Text is decided by extension, never by sniffing: `.rs
.ts .tsx .mts .cts .js .jsx .mjs .cjs .py .toml .json .jsonc .yml .yaml .md .html .css .txt .sh .ps1
.xml .svg .csv .tsv .lock`, plus `LICENSE*` and `COPYING*`. Exempt from the email rule only:
`package-lock.json`, `Cargo.lock` and `THIRD_PARTY.md`.

**Tests**:

1. The walk found the tree: more than N files (about half the current count).
2. No control characters other than tab, LF and CR.
3. No home-directory paths: `(?:[A-Za-z]:[\\/]+Users[\\/]+|/home/|/Users/)[A-Za-z0-9._-]+`.
4. No email addresses except `^\d+\+[A-Za-z0-9-]+@users\.noreply\.github\.com$`,
   `^noreply@(?:anthropic|github)\.com$`, `@(?:example|invalid|localhost|test)(?:\.[A-Za-z]{2,})?$`,
   `\.(?:example|invalid|test)$`.
5. No secret-shaped strings: `pk_(?:live|test)_[A-Za-z0-9]{16,}`, `pbt_[A-Za-z0-9]{16,}`,
   `sk-[A-Za-z0-9_-]{20,}`, `AIza[0-9A-Za-z_-]{35}`, `gh[pousr]_[A-Za-z0-9]{30,}`,
   `github_pat_[A-Za-z0-9_]{30,}`, `xox[baprs]-[A-Za-z0-9-]{10,}`,
   `-----BEGIN (?:RSA |EC |OPENSSH |)PRIVATE KEY-----`. The one allowed token is the `pat_…` app
   token inside `crates/keepers-publik/publik-app-token.txt`.

Failure messages say what to do: "use a path relative to the repository root, or an environment
variable"; "a real address in a public repository cannot be taken back"; "write the character as an
escape sequence"; "remove the key and rotate it". Proof (never committed): plant a home path, an email
at a real-looking domain, a 40-character fake `sk-` key and a control character in an untracked temp
file, see exactly four failures, then delete the file (module 00, acceptance test 6).

## 9. CI matrix

| Job | Runners | From module | What |
|---|---|---|---|
| `verify` | windows-latest, ubuntu-latest (+ macos-latest from 11) | 00 | `npm ci --prefix app`, then `scripts/verify.sh` under bash; Ubuntu installs Tauri's documented Linux prerequisites |
| `raw-samples` | ubuntu-latest | 01 | restore or download samples by checksum; run the tests that need them |
| `models` | ubuntu-latest, windows-latest | 03 | restore or download models by checksum; run model tests and the CC0 eye gate |
| `e2e-smoke` | ubuntu-latest | 06 | build the app, run the smoke under xvfb with tauri-driver |
| `release` | all three | 11 | on a `v*` tag: verify, build, draft the release from `docs/releases/<version>.md`, publish when green |

Caches are keyed by `Cargo.lock`, `app/package-lock.json`, `raw-samples.toml` and `models.toml`.

## 10. Manual checklist, by screen

Run before a release on Windows (and macOS from 11), with a real shoot of the tester's own.

- **Home**: empty state sentence; recent shoots list; a moved folder shows "folder not found".
- **Models setup**: sizes shown before download; cancel mid-download then resume; offline message.
- **Grid**: 3,000 frames scroll without stutter; thumbnails fill in; group badges; filters combine;
  "No frames match these filters."; status bar counts match the filters.
- **Loupe**: fit and 100% zoom; Z jumps to faces; face boxes line up on rotated (portrait) frames;
  EXIF line correct against the camera's display.
- **Compare**: 2, 3 and 4 up; synced zoom and pan; reasons visible.
- **Keyboard**: every key in the module 06 map; auto-advance on and off; undo and redo.
- **Cull panel**: each control changes counts; a user decision survives every control.
- **Export**: dry-run numbers; open the result in each editor you use and check ratings, labels and
  rejects appear (Lightroom Classic: Metadata > Read Metadata from Files; Capture One and darktable as
  their documentation says); export undo restores the prior sidecars.
- **Second opinion**: off by default; enable dialog strings and permission box; $0.00 card with three
  options; local model path with Ollama; one real call shows the charge; a 402 shows one link.
- **Style**: "Not enough history yet" before training; the change count; Reset.
- **Install** (11): per-user install with no administrator prompt; the SmartScreen steps in
  `RELEASING.md`; update check switch.
